# Windows string catalog

The Windows app renders its own labels, messages and accessible names from
`catalog/source/en-US.ftl`. Only `en-US` is included in production. The Rust
resources in `crates/observer-model/i18n/generated/` and ESM resources in
`i18n/generated/` are built from the same catalog.

The native shell reads the signed-in user's preferred app languages through
`GlobalizationPreferences.Languages`, falling back to
`GetUserPreferredUILanguages`. Fluent language negotiation chooses the first
supported match, then `en-US`. The available set is generated from the
production resources. Selection lasts for the process; changed preferences
apply on the next launch. The web UI receives this selection from Rust.

WebView2's environment uses the selected language for its own menus and dialogs.
Every window uses the existing shared profile directory and browser options.
Windows regional format is supplied separately for explicit JavaScript `Intl`
formatting. English retains the existing date and duration presentation.
Other languages retain Fluent's interpolation isolation, and the document sets
its language and text direction before rendering.

## Editing and regenerating

Use the compiler source revision and registry digest in `compiler.json`.
Build that compiler with its locked dependencies, then run:

```sh
I18N_COMPILER=/path/to/i18n-catalog node scripts/i18n.mjs
make ci
```

Follow the compiler's `tools/i18n/README.md` for source locks, sidecar revisions,
history and retirement. Each message has a stable identity and a sidecar with
its arguments, context and risk. Changed argument contracts need new identities.
Use whole messages with named arguments, including plurals and durations.
Update `source_revision` from the compiler's source lock before regenerating.

`make ci` checks the committed catalog, pin and generated bytes against their
snapshot. A generated-output-only edit fails. That offline check does not run
the compiler; regeneration requires the pinned compiler. Do not update the
snapshot by hand. Native app-crate build and tests run through `win-host-ci`.

Adding an approved language requires its catalog and registry membership,
regeneration, review and a rebuild. No application language list is maintained
by hand. Pseudolocales belong only in scratch catalogs and test builds.

## Boundaries

AutomationIds, IPC/state tokens, paths, file formats, private-window matchers,
physical keyboard key names and diagnostic logs remain stable identifiers or
technical data. Brand and platform names remain literal. Text supplied by the
owner, Windows, or the paired journal is data rather than a local message.
The native browser-host About base line remains an English protocol value;
its owner-visible version line is rendered separately from the catalog.

The app's update settings and status use this catalog. Velopack owns its Setup,
Update and uninstall dialogs and bundled translations. Version 1.2.0 provides
no application-catalog override. Its locale can differ from the app's selected
locale. The Start menu, shortcut, notification header and uninstall identity
retain the brand name `solstone` (and publisher `sol pbc`). Release notes are
release content, separate from this catalog.

The portable profile permits one plural select per message. Existing compact
hours/minutes patterns keep two display arguments so their units and order can
be translated. Machine-oriented ungrouped numbers retain their explicit numeric
style. This conversion does not certify a right-to-left layout or translated
Windows system UI.
